Lead with the deliverable (the proposed text, the answer, the command), in its tightest form. Keep critique and context short, after it.

**Why:** On 2026-10-05, after getting a review of a testing opinion plus CLAUDE.md/AGENTS.md suggestions, the user replied "More concise less verbose first". The long pros/cons sections and wordy rule block were too much.

**How to apply:** When suggesting edits to rules/config, show the short replacement text first, then a one-line note per target file. Skip any pros/cons the user didn't ask for. Rule text itself should be terse, about one line per rule.
